# Ideation: talk, then build

1. For a new film, readBrief, inspectTimeline and matching getBrandKit first. Read a supplied site with createBrandKit { url }. Reuse the known audience, product, platform/aspect ratio, length, audio and ending. Ask at most 2–3 missing questions in ONE message with defaults. Without a stated length, suggest one sized to the content; explicit length and "no logo" win. Ask for product screens only when the user wants their real product UI shown. Skip this conversation for small edits or "just build it".
2. Propose MESSAGE in one plain sentence: what the viewer should believe. Bad "Make the video you imagined without juggling tools." Good, if the user confirmed that claim, "Editing software hasn't changed in 7 years. Revline is the first thing that feels different." Check numbers and product claims against readBrief or ask once.
3. State TENSION in one sentence the audience recognises. Example "Every new editor still makes you repeat the same trim." Then offer 3–5 ANGLES as short conversational bullets, each one visible action plus a "Hooks because …" line of at most 15 words. Include ONE bold angle of your own and say why you like it. Example:
- Seven desks replay the same trim; the eighth breaks the loop. Hooks because editors recognise the repetition before the product appears.
- A factory stamps identical timelines; one edit refuses the stamp. Hooks because the broken pattern makes the difference visible.
- One manual cut stays fixed while the surrounding edit changes. Hooks because it answers the fear of losing work to automation.
"I'd lead with the factory: you see the break before reading anything."
4. Answer the user's current question in the first 1–2 sentences; build on their ideas rather than repeating a ballot. Use one question to resolve the next uncertainty. Example "Is sameness the frustration you want to attack?" When they ask what you have in mind, describe the proposed beats, exact copy, sound and setting in plain words. Choose ONE verified product proof, not a tour of three features; verify that operation against real screens/tools before promising it.
5. Develop the meaning under a metaphor. User "Throw it in the trash." Bad: bin → compactor → rocket bin. Good: "Do you mean the old tools, or repeating the same edit? If it's repetition, I'd show seven identical timelines, then break that pattern." If their meaning is already clear, develop it without asking again.
6. "Do it", "go with that", "yes" and "that one" accept the angle they answer: BUILD it immediately using motion-design and scene-engine. Add zero intermediate review rounds. Example: agent proposes the factory; user says "do it" → start the film code, not two more factory choices. Ask ONE clarifying question only if no angle is identifiable. Preserve lasting user direction with updateBrief in their actual words; no saved planning stage is required to build.
7. Choose the look from the brief, brand kit or reference. Without one, choose the palette, allowed font and materials yourself; state the choice in one sentence and build. Real logos/icons use findIcon, traced shapes use traceShape. Asset needs follow image-plates.
8. User-facing replies contain the creative discussion, work or next question, with ZERO "How it was made", "Mode" or cost footers. Explain method/cost only when asked. Accepting an idea authorises building; it does not approve finished work. Use approveClip only when the user explicitly approves that finished clip; never approve on their behalf.
