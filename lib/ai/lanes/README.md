# Editing lanes

Each folder owns its definition, skill wrappers, explicit tool additions and completion check. Existing skill bodies remain in `lib/ai/skills`; wrappers avoid copying those instructions. `options.ts` is the small client catalog. The recreation lane is hidden in the production picker unless internal details are enabled.

`base-tools.ts` is an explicit shared allowlist. New tools are denied until registered here or in a lane. `readSkill` validates the lane at execution. `analyzeMedia` also checks its mode, so it cannot expose reference analysis through a shared tool.

The editing agent chooses its own lane and edit/question intent through `switchLane` before any lane tools or skills are exposed. It reads one line per lane plus the user request, project brief and media context. `/clip` and manual composer choices are locked; follow-ups confirm the current lane unless the kind of work changed. There is no separate classifier, keyword router or duration heuristic. Real timeline tools promote finish enforcement even if the agent initially chose question.

The shared `runEditorTurn` serves Cloudflare and Convex. `prepareStep` sends only the lane's tools; middleware checks and logs the actual provider list. History filtering removes other lanes' tool and skill results while keeping the user's chat. Task and lane state live in `editingLaneTasks` and `editingLaneTabs`.

`finish` validates each touched timeline, refuses empty visual output and new coverage gaps, renders changed ranges, runs the lane's check, then publishes any checked draft. No model-provided scores or counts are accepted. Failure attempts persist across automatic restarts and lane switches. Three failures end the task with the actual check output. An explicit `/clip` task keeps that lane until a new user request, so missing tools cannot become a switch that bypasses clipping checks. Completion prose is suppressed until checks and publication succeed; questions use `askUser`.

MCP `startTask` creates a stable task ID and, without an explicit lane, exposes only selection controls until the agent calls `setLane` with its choice, reason and edit/question intent for one authenticated connection. `setLane` preserves its failure budget. Tool lists are filtered per connection; response SSE emits `notifications/tools/list_changed`. Cached clients receive the lane ownership/switch error before execution.

The upstream persisted candidate ledger and worker receipts supply found/accepted/tab counts. `mcp-task:<uuid>` is used verbatim as the ledger `runId`, independently of each MCP execution run. Only snapshot worker completion writes check receipts; completion rechecks the current tab fingerprint and rejects an untrusted or stale supplied draft. Preserve PR #58’s deterministic `finalMessage` close-out when resolving the shared `editorTurn` integration. Deploy the merged Convex functions and matching Cloudflare runner together, with a contract-38-capable processor. Live ledger/UI verification remains pending.
- Reference motion (#51): recreate owns motion coverage and completion; motion applies these checks only to a film already bound to a reference. Finish reads `referenceMotion.state` using the film's reference/range, current revision, `motionTimelineKey`, full-frame scope and aligned offset. Whole-film pixel review uses real paired samples at 10 fps, with no pixel-score pass threshold. Timed OFF exceptions clear their windows and persist in the finish result and final close-out, always marked not matched. Publishing a draft requires motion checks at its new revision. Other lanes do not run these gates or reports; never parse display-only `motionStatus()` as evidence.
- Main includes link imports (#53), R2 frame caching (#54) and Inspo Motion retirement (#56). Frame reads use the shared cached paths; only `/clip` is a slash command. No pending registration hooks remain for these integrations.
