# Editing workflows and supporting capabilities

`edit` is the compatibility value for shared editing without a selected style. The lanes are `edit`, `clip` and `reel`. The picker offers Auto and optional primary workflows; stored `edit` and MCP `setLane` remain valid. Stored `motion`, `recreate` and `explainer` values from removed lanes read as `edit`. Shared trims, captions, audio and timeline operations work immediately after task creation. Timeline writes still promote finish enforcement, including requests initially marked as questions.

The primary workflow owns the deliverable and completion checks. `/clip` and an explicit style pin it for the request. `discoverCapabilities(query)` returns at most five matching workflow/skill descriptions. `loadCapability(name)` adds supporting tools and a small skill index; `readSkill(name, page?)` loads one body/page and its tools. Neither changes the primary workflow, task ID, failure budget, clipping ledger or user decisions. Capabilities persist on the owner-checked task across continuations and MCP calls.

The app exposes shared tools plus primary and loaded supporting tools on each step. MCP tools/list returns the full, stable catalog for the whole session, so clients that never re-fetch it (Codex ignores `notifications/tools/list_changed`) still see every tool. Each call enforces owner, task, lane and capability: a lane or capability tool called before its lane is chosen or its capability is loaded returns the exact `loadCapability` step to take. Full skill text is not injected eagerly.

## Check levels

Each lane's `definition.ts` owns its check recipe. The lane is the only thing that changes which checks or tools run; model and reasoning effort stay user choices and never change them. The app and MCP read the same recipe from the task row.

- `edit`: timeline-data checks; `finish` draws at most 4 frames of what changed (new cuts, new overlays, one caption sample) and returns them. No frame per change, no whole-video sweeps.
- `reel`: saved-data checks (retained ranges, linked audio, caption words, timing and layout); `finish` draws at most 3 frames itself; no per-cut or per-caption frames.
- `clip`: two paths, told apart by `cutsGiven` (`clip/check.ts`). Moments Revline chose (the task ran `findHighlights`/`planClips`, or its request asked for them: `findMoments` on the task row, set by `lanes.begin` from the `/clip` command or wording such as "find the best moments"): finishClipping data checks against the registered plan; visual confirmation only for action moments. Cuts at source ranges the request named (neither signal): `finish` needs no plan and no whole-source analysis and runs the cheap checks only: timeline data, 15–60 s per new tab, populated source footage and the frames at every cut edge.

One automatic step-up, the `final` level, runs the lane's full checks (clip: checkClip decode-health on every accepted tab; clip finish never requires rendered frames). The server sets it in `lanes.begin` from the request: a final export or publish request, or an explicit request to double-check everything. The agent never chooses it. Stored `editMode` values on older queue rows, turns, runner checkpoints and browser storage still validate and are ignored.

History keeps source evidence and edit receipts across workflow changes. Only obsolete instruction results are retired; tool pairs remain valid. Older bulky results retain bounded structured IDs, findings and receipts, and omitted turns carry forward bounded user decisions and evidence. Current user instructions always take precedence.

Reel means one coherent short-form rough cut: transcript/audio first, false starts and accidental repeats removed while preserving full meaning and natural delivery, with targeted visual inspection as needed. Duration follows the message unless specified. New captions share minimal static, transparent-background creation defaults. Existing captions retain their styling. No automatic normalization or decoded-opening/full-film QA is required; structural, changed-range and applicable transcript-sync checks remain real.

## Script understanding and eyes

The reel lane reads a take as a script before cutting: `readScript` (deterministic outline: lines, opening, closing, repeated takes, chatter, b-roll shots) then `planScript` (the model's beats and priorities; saved on the task row as `script`, returns the ranges to cut). `finish` holds the cut to that plan. An app reel request on a raw take refuses the first speech cut until the plan exists; MCP flows without a plan are unchanged.

After any speech cut, in every lane, `readCutScript` reads the cut back (`lib/ai/lanes/reel/cut-script.ts`): the surviving words in timeline order from each clip’s source range and the saved word timings, with flags for a repeat, a clipped word, a half sentence and a long pause. `remove` cuts flagged repeats and false starts out in one change. A task that read its cut is held to it by `finish`, which fails on unaccepted flags that sit at a cut. It hears only what the transcript holds. Speech cuts on plain footage and clips that only moved queue no rendered frame checks (`speechCutMoments`, `FastFrameReview.changed`): gaps and overlaps are timeline data.

Eyes are one shared layer in `lib/ai/eyes` (measured face signals from the media worker's `looks` read, flags, a per-task frame budget, strips of about 480 px frames) with a per-lane policy on `LaneDefinition.eyes`: which spots, which flags, how many frames, what fails `finish`.

- `reel` (enforced): speech edges plus the first and last frame; `checkSpots` measures, shows 3 frames per flagged spot, one extra round of 5, 27 per request; `finish` fails on an unreviewed flagged first or last frame and reports the rest. B-roll: shots with no face, one frame each, at most 6.
  When no measurement exists the reel check warns ("cut edges could not be measured on this server; not verified") and `finish` passes: `REEL_LOOKS=off` on the Convex deployment switches the looks read off (default on), and a media processor older than the looks read answers with a frame sheet and no face samples, which counts as unmeasured. Looks results are cached under a key carrying `LOOKS_READ_VERSION`, so an old processor's entries are never read back. B-roll detection then reports itself unavailable and keeps wordless shots between saved scene cuts.
- `clip` (slot): policy declared (clip edges; no gaze rules), not applied by any tool or by `finish`. Separately from the policy, `finish` on a range-cut clip reads five frames at each cut edge with the same `looks` read (`clip/edges.ts`) and fails on one to three stray frames of a neighbouring shot; when the read is unavailable it warns and passes, as the reel check does. Its own detectors (cut mid-action, facecam cropped out, black or blurred frame, UI over the subject) are not built.
- `edit`: no eyes policy; `finish` draws its own frames on the budget in `task.ts` (`finishFrameBudget`).
