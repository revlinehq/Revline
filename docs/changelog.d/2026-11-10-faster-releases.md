- Releases: changelog entries are one file per pull request under `docs/changelog.d/` (assembled by `scripts/changelog.mjs build` at release time), every pull request runs `scripts/compat-check.mjs` (iOS-called Convex functions, media-processor capabilities, schema), and `npm run release:prod` releases production in one ordered, verified command with `npm run release:status` showing what is deployed; see `docs/releases.md`. Why: about 15 of 30 merges conflicted on `docs/changelog.md` and two production releases were stopped at deploy time by cross-version breaks (#243, #268), so getting merged work onto production took hours.
- Media processor: processors report what they can do when they sign in to the queue (`lib/server/processor-capabilities.ts`), Convex stores the last report per backend and `processorCan(ctx, 'read:looks')` decides whether the looks read is queued; the "no samples means unmeasured" check stays as the fallback. Why: #268 depended on a read mode the deployed processor answered with an empty success.
- Railway: `scripts/railway-proof.mjs` produces the staging promotion receipt by running the three proof jobs as the staging service identity `service:railway-proof`, and `railway-workers.mjs stage --founder-bypass "<reason>"` skips the receipt for one logged run. Why: the processor could not be promoted without a person running the staging jobs, and a founder-approved bypass needed a hand-edited copy of the script.
