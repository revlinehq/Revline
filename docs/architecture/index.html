01 / System

What runs, and who talks to whom

Screen

The browser and native app send requests and watch Convex subscriptions.

Saved truth

Convex owns projects, chat, permissions, revisions, tasks and export status.

Slow work

The runner executes agent turns. Processors handle media. Fly machines render exports.

Arrows show requests or data transfer. Responses return on the same connection. Repeated Convex labels refer to the same two deployments. On a phone, swipe the diagram sideways.

02 / Flows

Follow a request to its saved result

Each numbered step names the file and function to open. Function names are search targets. Large files often hold several steps.

A

Upload or import a video

  1. Pick a local file.

    The workspace and editor wire upload callbacks to Convex. uploadSourceFile checks the file, reads metadata and opens a multipart transfer.

    components/workspace/new-conversation.tsx · components/editor/connected-editor.tsx · handleUpload · lib/editor/upload-source.ts · uploadSourceFile · lib/editor/media.ts · inspectMedia
  2. Reserve space and authorize parts.

    start → openUpload checks access and capacity. createLease reserves storage and records the transfer. partUrl → signPartUrl signs one part and byte size.

    convex/r2.ts · start, openUpload, createLease, partUrl, signPartUrl
  3. Send bytes straight to R2.

    The browser PUTs each part to the media Worker. Its fetch verifies the signed grant and streams the body to the bucket. Convex does not relay every source byte.

    lib/editor/media.ts · uploadMultipart · cloudflare/media/worker.ts · fetch, /part
  4. Save the source, then prepare it.

    complete → completeUpload → finish checks the assembled object and creates the asset. Video queues extract, preview and understand. The source stays saved if the browser closes.

    convex/r2.ts · complete, completeUpload, finish · convex/mediaTasks.ts · enqueueMediaTask
  5. For a link, queue a download instead.

    onImportVideo waits for saves. importVideo → importVideoFor checks the URL and range, deduplicates work, and queues import. At most three imports may run for a project.

    components/editor/connected-editor.tsx · onImportVideo · convex/mediaTasks.ts · importVideo, importVideoFor
  6. The worker downloads and stores the link.

    processMediaTask calls importVideoLink. YouTube uses yt-dlp. Direct MP4 downloads validate public addresses. uploadMediaFile sends the result through R2 with the task lease.

    lib/server/media-task-runner.ts · processMediaTask · lib/server/import-video-link.ts · importVideoLink, videoResponse, publicAddress · lib/server/upload-media-file.ts · uploadMediaFile
  7. Place the imported clip and update Sources.

    The import completion handler calls placeImportedVideo unless sources-only was requested. An active agent edit defers placement through placeImport. It also queues extraction, preview and understanding.

    convex/mediaTasks.ts · import completion, placeImportedVideo, placeImport
Common job lifecycle. enqueueMediaTask → process → prepareAttempt makes work claimable. startMediaWorker subscribes, claims and renews a 60-second lease every 20 seconds. The workflow allows three attempts. Completion must match the active lease. convex/mediaTasks.ts · lib/server/media-worker-loop.ts · startMediaWorker · lib/media-analysis/errors.ts
B

Open the editor and prepare playback

  1. Authenticate and load the saved edit.

    EditorPage protects the route. ConnectedEditor subscribes to projects.get. readProject joins the project with separate run, timeline and scene records.

    app/(dashboard)/editor/[projectId]/page.tsx · EditorPage · components/editor/connected-editor.tsx · ConnectedEditor · convex/projects.ts · get · convex/lib/project_data.ts · readProject
  2. Check used video sources.

    createPlaybackOpeningGate waits only for used video above 64 MiB that lacks a preview. Smaller originals can open directly. The gate opens once. The UI shows “Preparing playback” while it waits.

    lib/editor/editor-opening.ts · createPlaybackOpeningGate · lib/editor/preview-source-cache.ts · MAX_PREVIEW_BYTES · components/editor/connected-editor.tsx · ProjectEditor, pendingPlayback
  3. Queue missing playback copies.

    playback.prepare checks the project and queues deduplicated preview tasks. Asset and task subscriptions show progress. Retry calls the same mutation. Audio preparation is checked separately.

    convex/playback.ts · prepare · lib/editor/editor-opening.ts · editorAudioPrepared · components/editor/connected-editor.tsx · preparePlayback
  4. Encode the proxy.

    processMediaTask calls preparePreviewVideo. It creates an H.264 MP4 with a longest edge of at most 1280 pixels. It preserves frames and source timing. A duration difference above 0.1 seconds fails validation.

    lib/server/media-task-runner.ts · processMediaTask · lib/server/preview-video.ts · preparePreviewVideo
  5. Attach the proxy to the original asset.

    uploadMediaFile stores it with purpose: preview. r2.finish records its key, size, dimensions and version. Live asset updates clear the opening gate.

    lib/server/upload-media-file.ts · uploadMediaFile · convex/r2.ts · finish
  6. Play, refresh and recover.

    Preview builds the composition for the HyperFrames player. The preview cache may download bounded files into memory. playback.refresh renews signed URLs. Recovery can reload a stalled source at its current position. Exports still use originals.

    components/editor/preview.tsx · Preview · lib/editor/preview-media-session.ts · createPreviewMediaSession · lib/editor/preview-source-cache.ts · createPreviewSourceCache · convex/playback.ts · refresh · lib/editor/media-source-recovery.ts · recoverMediaSource
C

An agent edit turn

  1. Send a prompt after local saves.

    The assistant panel uses EditComposer. ProjectEditor.sendRequest waits for media preparation and manual saves. It sends the prompt, selection, attachments and explicit timeline ID to Convex.

    components/editor/assistant-panel.tsx · AssistantPanelBody, submit · components/workspace/edit-composer.tsx · EditComposer · components/editor/connected-editor.tsx · sendRequest
  2. Record the request and take the edit lock.

    assistant.send checks access and context. Busy projects queue requests. beginRequest selects the requested tab, saves the user message, assigns a run ID and records aiRunning in one transaction.

    convex/assistant.ts · send, beginRequest · convex/schema.ts · assistantQueue, aiRuns
  3. Start a durable runner turn.

    startRunnerTurn schedules start and a watchdog. start signs a POST to /runs. Worker fetch checks the signature and nonce. EditorTurn.begin starts an idempotent fiber.

    convex/agentRunner.ts · startRunnerTurn, start · cloudflare/agent-runner/worker.ts · fetch, EditorTurn.begin
  4. Load context and run the model.

    EditorTurn.turn claims an attempt and sends heartbeats. runEditorTurn loads project context, memories and the brief. It selects the configured model and builds the shared tools before streaming text.

    cloudflare/agent-runner/worker.ts · EditorTurn.turn · convex/lib/editorTurn.ts · runEditorTurn · lib/ai/claude-model-policy.ts
  5. Call tools through a guarded bridge.

    createEditorToolkit defines inspect, edit, media and scene tools. Skills load on demand through readSkill. Signed bridge calls return to an allowlist of Convex functions. Slow media tools enqueue durable tasks.

    convex/lib/editorToolkit.ts · createEditorToolkit · lib/ai/skills/index.ts · editorSkillInstructions · cloudflare/agent-runner/convex-bridge.ts · convexBridge · convex/agentRunnerHttp.ts · authorizedRun, resolve
  6. Validate and save timeline changes.

    EditSession saves ordinary edits as it goes. Timing changes and deletions start a private draft. assistant.apply verifies the run and expected revision. commitTimeline and writeProject save the new revision, history and source code references.

    convex/lib/editSession.ts · EditSession · convex/assistant.ts · apply, previewDraft · convex/lib/timeline.ts · commitTimeline · convex/lib/project_data.ts · writeProject
  7. Publish and unlock.

    The loop checks tool failures and required review evidence. EditSession.complete publishes a successful draft. assistant.finish clears the run lock. Convex subscriptions deliver saved edits and chat messages.

    convex/lib/editorTurn.ts · runEditorTurn · convex/lib/editSession.ts · complete · convex/assistant.ts · finish

Fallback: if runner settings are absent, assistantWorkflow.runTurn → assistantActions.respond runs the same loop in a Convex action. convex/assistantWorkflow.ts · convex/assistantActions.ts · respond

MCP joins at the same tools: forwardToMcp → mcpHandler → mcpAuth.authenticate → mcpActions.callTool → callEditorTool. Mutating calls use a run lock and EditSession. Passing timelineId avoids acting on another session’s tab. proxy.ts · forwardToMcp · convex/mcpHttp.ts · mcpHandler · convex/mcpAuth.ts · authenticate · convex/mcpActions.ts · callTool, callEditorTool

D

Export a saved timeline

  1. Press Export.

    ExportDialog.startExport sends settings. exportVideo waits for manual saves and calls renders.start.

    components/editor/export-dialog.tsx · ExportDialog, startExport · components/editor/connected-editor.tsx · exportVideo
  2. Validate and freeze the input.

    startRenderFor checks access, resolution, duration and queue limits. saveRenderSnapshot captures the selected saved timeline. It creates a renderJobs row and linked render task. Later edits do not rewrite this snapshot.

    convex/renders.ts · start, startRenderFor · convex/lib/render_snapshots.ts · saveRenderSnapshot · convex/mediaTasks.ts · enqueueMediaTask
  3. Ask Fly for capacity.

    With RENDER_PROVIDER=fly, prepareAttempt schedules flyRender.dispatch. It checks account seats and lane caps, then starts warm machines or creates burst machines. A minute cron also dispatches waiting jobs.

    convex/mediaTasks.ts · prepareAttempt · convex/flyRender.ts · dispatch, demand, machineConfig · convex/lib/render_seats.ts · seatedRenders · convex/crons.ts
  4. Claim the snapshot and render.

    The Fly export-only consumer claims one eligible job. processMediaTask prepares the composition. Plain timelines can use FFmpeg. Other edits use writeComposition → runRenderWorker for browser rendering. Failed fast paths can fall back to the browser.

    infra/media-worker/consumer.ts · lib/server/media-worker-loop.ts · startMediaWorker · lib/server/media-task-runner.ts · processMediaTask · lib/server/plain-export-render.ts · renderPlainExport · lib/server/render-worker.ts · runRenderWorker
  5. Store the MP4 before declaring success.

    uploadMediaFile writes R2 output. r2.finish records outputR2Key at 99 percent. The render completion handler checks that output, then marks the job completed at 100 percent.

    lib/server/upload-media-file.ts · uploadMediaFile · convex/r2.ts · finish · convex/mediaTasks.ts · render completion
  6. Authorize the download.

    onDownloadExport calls renders.download. downloadSource verifies ownership and completion. mediaDownloadUrl signs an attachment read. The browser downloads through the R2 Worker.

    components/editor/connected-editor.tsx · onDownloadExport · convex/renders.ts · download, downloadSource · convex/lib/media_storage.ts · mediaDownloadUrl · cloudflare/media/worker.ts · fetch, /read

Useful boundary: /api/render only authenticates and reads job status. It does not render the video. Distributed Fly rendering is opt-in and defaults off. app/api/render/route.ts · POST · convex/flyRender.ts · distributedExports

E

Clipping, speaker framing and loudness

  1. Measure the facecam before cropping.

    detectFacecam queues analysis. processMediaTask → detectSourceFacecam combines local MediaPipe face scans with OpenCV panel edges. The result can be overlay, creator-only, gameplay-only or uncertain.

    convex/lib/editorToolkit.ts · detectFacecam, analyze · lib/server/media-task-runner.ts · processMediaTask · lib/server/clipping-analysis.ts · detectSourceFacecam · lib/server/source-face-evidence.ts · scanSourceFaces · scripts/detect-facecam.py
  2. Apply a supported two-row crop.

    applyLayout → applyTwoRowLayout uses measured regions. detectedRegionForClip rejects weak or changing evidence. It changes crop and transform while preserving timing and sound.

    convex/lib/editorToolkit.ts · applyLayout · lib/editor/two-row-layout.ts · applyTwoRowLayout, detectedRegionForClip
  3. Match speech to a visible face.

    followSubject with active-speaker requests a window of at most 120 seconds. The processor reuses a transcript or calls Deepgram with diarization. trackSourceSpeakers samples face motion. matchSpeakingFaces compares mouth activity to speech turns. Weak matches stay unresolved.

    convex/lib/editorToolkit.ts · followSubject · lib/media-analysis/deepgram.ts · transcribeWithDeepgram · lib/server/clipping-analysis.ts · trackSourceSpeakers · lib/server/match-speaking-faces.ts · matchSpeakingFaces
  4. Save a measured framing path.

    speakerFocus smooths the focus path. focusForClip maps it into the selected clip. The tool checkpoints the change only when evidence supports it. Gemini fallback requires an explicit flag and key.

    lib/media-analysis/clipping.ts · speakerFocus · convex/lib/editorToolkit.ts · followSubject · lib/editor/operations.ts · focusForClip · lib/server/optional-gemini-vision.ts · optionalGeminiVision
  5. Measure the actual retained audio mix.

    normalizeAudio requests a snapshot. normalizeTimelineAudio includes timing, gain, fades and ducking. normalizeAudioFile uses two-pass FFmpeg EBU R128 normalization. Defaults are -14 LUFS and -1 dBTP.

    convex/lib/editorToolkit.ts · normalizeAudio · convex/mcp.ts · requestFrames · lib/server/media-task-runner.ts · snapshot task · lib/server/normalize-audio.ts · normalizeTimelineAudio, normalizeAudioFile
  6. Save and reuse the measured WAV.

    The snapshot completion checks output type and loudness. The tool saves a content key with the normalized audio. A changed mix or timing bypasses the old bake. Preview and export use the same WAV. Final export peak is checked again.

    convex/mediaTasks.ts · snapshot completion · convex/lib/editorToolkit.ts · normalizeAudio · lib/server/normalize-audio.ts · enforceNormalizedExportPeak

Normalization supports 0.3 seconds to ten minutes. Silent ranges and speed-ramped audio are rejected. lib/server/normalize-audio.ts

F

Two payment channels, one access decision

  1. Web: open checkout from the gate.

    EditorAccessGate observes plan status. createCheckout authenticates the Clerk owner and rejects existing Apple access or an active Stripe subscription. It reserves checkout and uses an idempotency key.

    components/workspace/editor-access-gate.tsx · EditorAccessGate, openCheckout · convex/billing.ts · createCheckout, reserveCheckout, saveCheckout
  2. Web: reconcile signed Stripe events.

    The /stripe/webhook handler verifies the raw signature. For subscription changes it claims a sync, fetches current Stripe state, then applies it. The claim prevents an older response from overwriting a newer result.

    convex/http.ts · /stripe/webhook · convex/billing.ts · beginSubscriptionSync, applySubscriptionSync
  3. iOS: show the paywall from backend status.

    PurchaseCoordinator.observe identifies Superwall with the Clerk user ID and watches billing:status. Existing web members bypass the paywall. presentPaywall uses placement onboarding_paywall.

    mobile/Revline/Billing/PurchaseCoordinator.swift · observe, presentPaywall
  4. iOS: bind a purchase to its owner.

    accountToken maps the Clerk owner to a stable UUID. purchase passes that UUID as StoreKit’s account token. The original signed transaction goes to syncTransaction. The client finishes only after server sync succeeds. Restore uses the same path.

    convex/appleBilling.ts · accountToken, owner · mobile/Revline/Billing/PurchaseCoordinator.swift · purchase, sync · convex/appleBillingActions.ts · syncTransaction, persist
  5. Validate server purchase events.

    Apple notifications verify signed data. Superwall webhooks verify Svix signatures and validate project, store, bundle, environment and owner. Both reach appleBilling.apply. It rejects stale events and ownership changes, and preserves refund state.

    convex/appleBillingHttp.ts · registerAppleBillingRoutes · convex/appleBillingActions.ts · notification, persist · convex/superwallBilling.ts · webhook · convex/appleBilling.ts · apply
  6. Join all access sources in Convex.

    billing.status combines active Stripe, verified Apple and complimentary access. requireEditorAccess enforces it on the server. hasUltraPlan sets higher limits. Upload and export checks use these shared predicates.

    convex/billing.ts · status · convex/lib/billing_access.ts · requireEditorAccess, hasUltraPlan · convex/lib/apple_entitlements.ts · activeAppleEntitlement · convex/renders.ts · startRenderFor · convex/r2.ts · authorize, createLease
Activation matters. Native Apple and Superwall billing is implemented but documented as not yet deployed or configured. Web Pro is defined as $39/month with a three-day first-subscription trial. ULTRA_OFFERED=false pauses the retained Ultra offer. When BILLING_ENABLED is not true, server payment gating returns early. mobile/README.md · lib/billing/plan.ts · convex/lib/billing_access.ts · requireEditorAccess

06 / Risks

Ten places to handle carefully

These are risk judgments based on the code paths below. They are not a list of confirmed incidents.

01 / Wrong environment

A correct deploy to the wrong backend

Web, runner, processor, Clerk and Fly settings must agree. One wrong URL or shared secret can route reads and writes into another environment. Use the deploy guards and setup report.

scripts/cloudflare-frontend.mjs · scripts/deploy-production.mjs · scripts/deploy-fly-exports.mjs · scripts/check-setup.mjs
02 / Saved edits

Revision checks touch every editor

Manual saves, agent drafts and MCP share the timeline commit path. Stale revisions, wrong tab IDs or late run writes can overwrite work if these checks change. Scene code and history are stored separately.

convex/lib/editSession.ts · convex/lib/timeline.ts · commitTimeline · convex/lib/project_data.ts · writeProject · convex/assistant.ts · apply
03 / Worker contracts

A mismatched release can strand tasks

Workers claim only compatible processor versions. The active attempt and lease control writes. Image, Convex contract, heartbeat and drain changes must agree. The release script verifies those boundaries.

lib/media-analysis/processor-version.ts · convex/mediaTasks.ts · lib/server/media-worker-loop.ts · scripts/deploy-production.mjs
04 / Compute spend

Both Fly lanes are large machines

Actual profiles use 16 performance CPUs, 32,768 MB and 20 GB scratch. Default machine caps are ten per lane. Machines can idle out, but warm machines retain their volumes. Check caps, cleanup and optional distributed fan-out before changing capacity.

convex/flyRender.ts · PROFILES, flyConfig, dispatch · convex/lib/render_seats.ts
05 / AI spend

Cost recording is not an enabled cap

Financial token-budget enforcement is off unless EDITOR_ENFORCE_TOKEN_BUDGET=true. Model calls, ElevenLabs, fal, Deepgram and Gemini can each spend separately. Clipping fallback has its own opt-in flag. Provider failures can also block preparation.

lib/ai/token-budget.ts · editorTokenBudgetEnabled · convex/lib/editorTurn.ts · lib/audio/voice.ts · lib/server/media-task-runner.ts · lib/server/optional-gemini-vision.ts
06 / Access to bytes

Signing protects a shared bucket

The two R2 gateways share storage. Bad grant scope or ownership checks can expose media. Runner callbacks can reach internal Convex functions, so their run scope and allowlist matter too. General and export-only keys have different rights.

cloudflare/media/worker.ts · lib/storage/media-tokens.ts · convex/r2.ts · convex/agentRunnerHttp.ts · convex/lib/media_task_auth.ts
07 / Destructive deletion

A storage delete can remove a project

storage.remove can delete projects whose edits use the selected media and remove shared attachments. This is broader than hiding a file from Sources. Preserve active export and agent protections.

convex/storage.ts · remove · convex/projectDeletion.ts
08 / Preview fidelity

Small timing changes reach the final film

Proxy timestamps, source offsets, scene frame clocks and normalized audio keys must stay aligned. Preview and export share much of the scene runtime. A changed mix must invalidate its old normalized WAV. Verify the final encoded peak.

lib/server/preview-video.ts · lib/editor/scene-runtime.ts · lib/editor/scene-react-runtime.tsx · lib/server/normalize-audio.ts
09 / Money and access

Late events can revive the wrong access

Stripe checkout reservations and subscription sync claims prevent duplicate or stale updates. Apple ownership and refund ordering protect restored access. Missing billing enablement permits unpaid edits. The native path still needs deployment and provider setup.

convex/billing.ts · convex/http.ts · convex/appleBilling.ts · apply, owner · convex/lib/billing_access.ts · mobile/README.md
10 / Imported URLs

A download is a network and disk boundary

Public address checks prevent imports from reaching private services. Size and free-disk checks bound downloads. yt-dlp can fail when upstream access changes. Preserve these checks when adding import sources.

lib/server/import-video-link.ts · publicAddress, videoResponse, importVideoLink · convex/mediaTasks.ts · importVideoFor
